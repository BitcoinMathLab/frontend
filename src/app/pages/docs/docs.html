Overview

An inspection layer for Bitcoin.

Bitcoin Math Lab turns serialized data, Script execution, stack transitions, and validation outcomes into experiences that can be inspected one decision at a time. The product is educational software: it does not hold keys, move funds, provide financial advice, or replace a fully validating Bitcoin node.

The first release follows one historical pay-to-public-key-hash spend. The growing explorer can also retrieve confirmed mainnet transactions from Bitcoin Core and divide their serialization into inspectable fields without accepting or broadcasting transaction data.

Transaction explorer

Follow bytes from serialization to meaning.

Enter any confirmed mainnet transaction ID, or begin with a verified educational fixture. Bitcoin Core supplies the transaction and its previous outputs; the explorer then presents input spend paths, created outputs, value and fee totals, identifiers, and SegWit-aware size metrics.

  1. Choose a byte range. The inspector maps version, CompactSize counts, outpoints, scripts, sequences, amounts, witness items, and locktime to exact zero-based byte offsets.
  2. Read the decoded value. Little-endian integers, reversed transaction IDs, standard locking programs, sequence semantics, and locktime meaning are explained beside the selected bytes.
  3. Walk through or copy exact bytes. Use Previous/Next, Arrow keys, or Home/End to move through fields with keyboard focus. Long values use compact on-screen previews, while Copy bytes always places the complete selected field on the clipboard.
  4. Keep node authority clear. The browser explains canonical bytes returned by the product API. Bitcoin Core remains the source for mainnet transaction data and the product never requests private keys.

A transaction must already be known to the connected node. The explorer cannot find unconfirmed data absent from that node, recover deleted transactions, or prove that an arbitrary script is spendable merely by recognizing its template.

Development principles

Correctness before spectacle.

  1. Show the mechanism. Prefer actual bytes, opcodes, and state changes over an analogy that hides them.
  2. Keep boundaries testable. Engine, API, and browser contracts are verified independently and together.
  3. Make failure educational. Invalid spends return inspectable traces and safe diagnostics, not raw exceptions.
  4. Stay honest about authority. Bitcoin Core remains the production source of truth for network validation.
  5. Ship narrow, complete increments. One polished P2PKH lesson comes before broad script or transaction coverage.

FAQ

Common questions.

Is Bitcoin Math Lab a wallet or node?

No. It is educational and developer software. The MVP uses curated transaction data and does not manage keys, broadcast transactions, or participate in the Bitcoin network.

Does Bitclone replace Bitcoin Core?

No. Bitclone makes selected mechanisms reusable and inspectable, while Bitcoin Core remains the production reference and network source of truth.

Why begin with P2PKH?

P2PKH is compact enough to follow in one sitting while still demonstrating stack data, hashing, equality verification, and signature checking.

Is the code open source?

Yes. The frontend, backend, and Bitclone repositories are public under the Bitcoin Math Lab GitHub organization.

Can I analyze any transaction?

You can look up confirmed mainnet transactions available to the connected Bitcoin Core node. The explorer decodes transaction structure and recognized standard spend paths; arbitrary script editing and professional debugging remain later work.
